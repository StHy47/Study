# 이더넷 Ethernet
### 정의
- LAN(특히 유선) 환경에서 대중적으로 사용됨
- 다양한 통신 매체의 규격들과 송수신되는 프레임의 형태, 프레임을 주고 받는 방법 등이 정의된 네트워크 기술
  - 집이나 사무실에서 컴퓨터, 스마트폰, 프린터, 공유기 등을 랜선(케이블)으로 연결해 데이터를 안정적으로 주고받을 수 있도록 만든 공통의 규칙(프로토콜)
- 이더넷 기술로 구현되는 계층 : 물리 계층, 데이터 링크 계

### 이더넷의 표준화
- IEEE 802.3 : 이더넷 관련 다양한 표준들의 모음
  - 모든 네트워크 장비( 허브, 스위치, NIC 등)은 특정 이더넷 표준을 따름
    - '특정 이더넷 표준을 지원한다', '특정 이더넷 표준과 호환된다'
  - 이더넷 작업 그룹의 이름이기도 함
- 이더넷 표준에 따라 지원되는 네트워크 장비, 통신 매체 종류와 전송 속도 등이 달라짐


### 통신 매체 표기 형태
- 보통 이더넷 표준 규격에 따라 구현된 통신 매체를 지칭할 때는, 통신 매체의 속도와 특성을 파악하기쉽게 표기
```
전송 속도 | BASE | - 추가 특성
```
#### 1. 전송속도 Data Rate
- 그냥 숫자 = Mbps 속도
- 숫자 + G = Gbps 속도
#### 2. BASE 베이스밴드
- 변조 타입 : 비트 신호로 변환된 데이터를 통신 매체로 전송하는 방법
- 보통은 디지털 신호를 송수신하는 베이스밴드 방식 사용
#### 3. 추가 특성
- 통신 매체 특성
  - 전송 가능 최대 거리
  - 물리 계층 인코딩 방식 : 데이터가 비트 신호로 변환되는 방식
  - 레인 수 : 비트 신호를 옮길 수 있는 전송로 수
  - 통신 매체 종류
  - ETC

 ### 통신 매체 종류
  | 추가 특성 표기(통신 매체의 종류) | 케이블 종류 |
  |---|---|
  | C | 동축 케이블 |
  | T | 트위스티드 페어 케이블 |
  | S | 단파장 광섬유 케이블 |
  | L | 장파장 광섬유 케이블 |


## 이더넷 프레임
- 정의 : 이더넷 네트워크에서 주고 받는 프레임
- 상위 계층에서 받은 정보에 캡슐화/ 역캡슐화를 통해 만들어짐
- 구성
  - 이더넷 프레임 헤더
    - 프리앰블
    - 수신지 MAC 주소
    - 송신지 MAC 주소
    - 타입/길이
  - 페이로드 : 데이터
  - 트레일러 : FCS

| 타입 | 필드명 (Field) | 크기 (바이트) | 역할 및 설명 |
| :--- | :--- | :---: | :--- |
| 헤더 | 프리앰블 (Preamble) | 7 | 수신 측 컴퓨터가 데이터가 오고 있음을 알 수 있음 |
| 헤더 | SFD (Start Frame Delimiter) | 1 | 프레임의 시작을 알리는 값 |
| 헤더 | 도착지 MAC 주소 (Destination MAC) | 6 | 이 택배를 **받아야 할 사람**의 집 주소 (랜카드 고유 번호) |
| 헤더 | 출발지 MAC 주소 (Source MAC) | 6 | 이 택배를 **보내는 사람**의 집 주소 |
| 헤더 | 타입 / 길이 (Type / Length) | 2 | 안에는 어떤 프로토콜(IPv4, ARP 등)이 들어있는지 알려주는 **표지판** |
| 페이로드 | 데이터 (Payload / Data) | 46 ~ 1500 | 실제로 전달하려는 진짜 내용물 (상위 계층의 패킷) |
| 트레일러 | FCS (Frame Check Sequence) | 4 | 데이터가 오는 동안 망가지지 않았는지 확인하는 **오류 검사** |

* **전체 프레임 크기:** 최소 64바이트 ~ 최대 1518바이트

#### 1. 프리앰블
- 송수신지 간의 동기화를 위해 사용되는 정보
- 8Bytes = 64BITS
  - 첫 7바이트 = 10101010
  - 마지막 바이트 = 10101011
- 수신자 : 프리앰블을 통해 이더넷 프레임이 오고 있음을 확인

#### 2. 송수신지 MAC 주소
- MAC 주소 = 물리적 주소
  - 네트워크 인터페이스마다 부여되는 6bytes(48bits) 길이 주소
  - LAN 내 수신지와 송신지 특정 가능
- MAC 주소는 고유하고 불변한 값을 사용하여, 네트워크 인터페이스마다 부여
  - NIC가 네트워크 인터페이스 담당
    - 한 컴퓨터 NIC 여러개 = MAC 주소도 여러 개 가능 (반드시 MAC 주소가 고유하지는 않을수도 있음)
- MAC 주소 확인
```
>getmac /v #윈도우 기준
연결 이름       네트워크 어댑터 물리적 주소         전송 이름
=============== =============== =================== ==========================================================
Wi-Fi 2         Intel(R) Wi-Fi  00-AA-00-0A-A0-0A   \Device\Tcpip_{000000AA-0000-0000-000A-000A000A0000}
Bluetooth 네트  Bluetooth Devic 00-AA-00-0A-A0-0A   미디어 연결 끊김
```

#### 3. 타입/길이
- 타입 혹은 길이가 필드에 올 수 있음
  - 1500(16진수 05DC) 이하 : 길이
  - 1536(16진수 0600) 이상 : 타입
- **타입**
  - 역할: 데이터(페이로드) 안에 상위 계층의 어떤 프로토콜(규칙)이 담겨 있는지 알려
  - = 이더타입
  - 상위 계층에서 사용된 프로토콜의 이름이 명시됨

    | 타입 | 프로토콜 |
    |---|---|
    | 0800 | IPv4 |
    | 86DD | IPv6 |
    | 0806 | ARP |

- **길이**
  - 역할: 뒤따라오는 데이터(페이로드)의 실제 바이트 길이



#### 4. 데이터
- 상위 계층에서 전달 받거나 전달해야할 내용
- PDU
- 최소 46바이트 이상 ~ 최대 1500바이트 이하
  - 최소 도달 못하면 패딩padding으로 정보를 채움 : 0으로 채움
 
#### 5. FCS
- 수신한 이더넷 프레임에 오류가 있는지 확인하기 위한 필드
- 오류 검출
- CRC값 (Cyclic Redundancy Check) = 순환 중복 검사
  1. 송신지에서 프리앰블을 제외한 CRC값 -> FCS에 저장
  2. 수신지에서 받은 값의 프리앰블과 FCS를 제외한 CRC값 계산 -> FCS와 비교
