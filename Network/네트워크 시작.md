# 1. 네트워크 개념

## 1-1. 네트워크 정의
  - 네트워크 = 컴퓨터 네트워크
  - 여러 장치 간 서로 정보를 주고 받는 통신망
### 인터넷
- 네트워크를 연결하는 네트워크

### 트래픽
- 네트워크 내 정보량
- **과부하** : 특정 노드에 트래픽이 몰려, 해당 노드가 특정 시간동안 처리해야할 정보량이 몰림
  - 과부하는 성능 저하로 연결됨.


## 1-2. 네트워크의 기본 구조
- 네트워크의 구성 요소 : 노드, 간선, 메세지

  <details>
  <summary>그래프 구조와 유사</summary>

  ### 그래프
  - 노드와 간선으로 구성된 자료 구조
  - 구성 요소 : 노드, 간선, 자료구조
    - 노드(node) = 정점(vertex)
    - 간선(edge) = 링크(link)
    - 자료구조 : 정보를 표현하고 다루는 방법

- 노드 : 정보를 주고 받는 장치
    - 특별한 노드 : 호스트, 중간노드
- 간선 : 정보를 주고 받는 유무선 통신 매체
- 메세지 : 노드 간에 주고 받는 정보


### 1-2-1. 노드

### 호스트
- 노드 중 네트워크의 가장자리에 위치한 노드
  - 네트워크의 정보 최초 생성 및 송신, 최종 수신
- (= 종단 시스템)
- 특정한 역할을 수행하는 호스트의 종류
  - 서버
  - 클라이언트
 
#### 서버
- 어떤 서비스를 제공하는 호스트
  - 서비스 : 파일 서버, 웹 서버, 메일 서버 등

#### 클라이언트
- 서버에게 서비스를 요청(리퀘스트)하고 서버 응답(리스폰)을 제공받는 호스트
- **예시**
  - 클라이언트 : 내 컴퓨터
  - 요청 : 구글에 귀여운 마루 사진 검색
  - 응답 : 귀여운 마루 사진 짠~


### 네트워크 장비
- 중간노드 : 호스트 간 주고 받는 정보가 중간에 거치는 노드
- 예시
    - 이더넷 허브
    - 스위치
    - 라우터
    - 공유기
 

- 호스트와 네트워크 장비는 배타적인 개념이 아님


### 1-2-2. 간선
### 통신 매체
- 호스트와 네트워크 장비 등 각 노드를 연결하는 간선
- 종류 : 유선 매체, 무선 매체
  - 유선 매체 : 노드를 유선으로 연결
  - 무선 매체 : 노드를 무선으로 연결
    - ex) 와이파이



 ### 1-2-3. 메세지
 - 통신 매체로 연결된 노드가 주고받는 정보
 - ex) 웹 페이지, 파일, 메일 ...

# 2. 네트워크 분류

 ## 2-1. 범위에 따른 네트워크 분류
 - 네트워크의 구성 요소가 모여서 형성된 네트워크의 범위는 다양
  - 가정, 기업, 도시 등

- 네트워크 범위에 따른 분류 : LAN, CAN, MAN, WAN
  - CAN : Campus Area Network 회사나 학교의 건물 단위로 연결
  - MAN : Metropolitan Area Network 도시 단위로 연결

### LAN
- Local Area Network
- 근거리 통신망
  - ex) 가정, 기업, 학교 등 한정된 공간
<img width="362" height="254" alt="image" src="https://github.com/user-attachments/assets/f3c0bdca-67e9-431e-912d-f8bebe7d9953" />

### WAN
- Wide Area Network
- 광역 통신망
  - ex) 인터넷
- 서로 다른 LAN에 속한 호스트와 메세지를 주고 받을 때 필요
- ISP(인터넷서비스제공업체)가 WAN을 구축하고 관리
  -  한국의 ISP : KT올레, SK브로드밴드, LG헬로비전 등
  - ISP는 WAN에 연결 가능한 회선을 임대해줌
    - 그래서 인터넷 사용 요금을 내는 것
   


## 2-2. 메세지 교환 방식에 따른 네트워크 분류
- 메시지를 주고 받는 방식 : 회선 교환 방식, 패킷 교환 방식


### 2-2-1. 회선 교환 네트워크
- circuit switching 방식
- 메세지를 주고 받기 전에 두 호스트를 어떤 경로로 연결할지 회선을 설정하고, 연결된 경로로 메세지를 주고 받음
  - **회선** : 메세지를 전송할 간선
  - 회선을 먼저 설정하고, 메세지를 주고 받음
    - 호스트 간의 회선을 어떻게 설정하는 가가 중요
- 장점 : 주어진 시간동안 전송되는 정보의 양이 비교적 일정
- 단점 : 회선 이용 효율이 낮아질 수도 있음
  - 어떤 회선이 메세지는 전송하지 않고, 연결만 되어 있는 상태이면, 필요한 노드에서 메세지를 보낼 수 없
  
#### 회선 스위치
- 호스트 간의 전송로를 확보하는 네트워크 장비
  - 철로의 선로 전환기와 같은 역할 : 해당 경로로 갈 수 있도록 해줌

### 2-2-2. 패킷 교환 네트워크
- packet switching 방식
- 메세지를 작은 단위인 패킷으로 쪼개어 전송
  - **패킷** : 패킷 교환 네트워크에서의 메세지 최소 단위
  - 패킷 크기만큼 분할되어 전송된 다음, 호스트에 도달하여 재조립됨
- 보통 인터넷이 이런 방식을 이용
- 장점 : 네트워크 이용 효율이 상대적으로 높음
  - 두 호스트가 하나의 전송 경로를 점유하지 않아서 메세지가 쉴 새 없이 전송됨
 
#### 패킷 스위치
- 패킷이 수신지까지 올바르게 전송되도록 최적의 경로 결정 및 패킷 송수신지 식별
- ex) 라우터, 스위치

- 페이로드
  - 패킷을 통해 전송하고자 하는 데이터
    - 택배 박스에 넣을 물건
  - 패킷 앞, 뒤로 추가되는 부가, 제어 정보 ( = 송장)
    - 헤더 : 패킷 앞
    - 트레일러 : 패킷 뒤


#### 주소
- 헤더에 포함되는 대표적 정보로, 송수신지를 특정하는 정보
    - ex) IP주소, MAC 주소
- 주소를 통해 메세지를 다양한 방식으로 전달 가능
    - ex) 특정 호스트를 수신지로 지정, 모든 호스트 지정 등
    - 전송 방식 : 유니캐스트, 브로드캐스트, 멀티캐스트, 애니캐스트 

- 유니캐스트 unicast
  - 가장 일반적인 형태
  - 하나의 수신지에 메세지를 전송하는 방식
    - 송신지와 수신지가 일대일로 메세지를 주고받음
- 브로드캐스트 broadcast
  - 자신을 제외한 네트워크 상의 모든 호스트에게 전송하는 방식
  - 브로드캐스트 도메인 : 브로드캐스트가 전송되는 범위, 수신지

# 3. 네트워크 배경지식
- 프로토콜 : 통신과정에서 정보를 올바르게 주고받기 위해 합의된 규칙
- 네트워크 참조 모델 : 통신이 일어나는 구조 계층화
- 캡슐화(역캡슐화) : 통신 과정에서 이루어지는 캡슐화

## 3-1. 프로토콜
- 노드 간 정보를 올바르게 주고받기 위해 합의된 규칙
- 서로 다른 통신 장치가 정보를 주고 받기 위해서는 프로토콜이 통해야함.
  - 통신 과정에서 하나의 프로토콜만 사용하지는 않음.
- 프로토콜마다 목적과 특징이 다름.
    - 프로토콜마다 패킷의  헤더 내용이 달라지거나 없을 수도 있음.
 

## 3-2. 네트워크 참조 모델
= 네트워크 계층 모델  

<img width="278" height="181" alt="image" src="https://github.com/user-attachments/assets/c0123a01-4a14-40f6-8529-047e10298dd3" />  


- 네트워크를 통해 정보를 주고 받을 때, 정형화된 단계(계층)을 거침
  - 통신 과정을 계층으로 나눈 구조
- 걔층화의 장점
  1. 네트워크 구성과 설계의 쉬움.
    - 각 계층별 수행해야 할 역할과 목적이 뚜렷함.
      - 계층의 목적에 맞는 프로토콜과 네트워크 장비를 계층별로 구성.
  2. 네트워크 문제 진단과 해결이 쉬움.
    - 문제 원인을 계층별로 진단하기 수월함.
      - 1계층 -> 2계층 -> 3계층 이런 식으로 단계별로 진단 가능.
     
- 네트워크 참조 모델은 반드시 지켜야 하는 형식인, 구조 이해를 위한 가이드라인.
     
### 네트워크 참조 모델 종류
#### 3-2-1. OSI 모델
   - 국제 표준화 기구에서 만든 네트워크 참조 모델. OSI 7계층
   <img width="141" height="274" alt="image" src="https://github.com/user-attachments/assets/d69370ed-b4e7-4859-8ba0-2d95b813750a" />
  
1. 물리 계층
 - 1과 0으로 비트 신호를 주고 받음
 - 통신 매체에 맞는 신호로 운반되도록 비트 데이터 변환, 통신 매체를 통한 송수신

2. 데이터 링크 계층
  - 네트워크 내 장치 간 정보를 올바르게 주고 받기 위한 계층
  - 물리 계층(1계층)의 정보에 오류가 없는지 확인
  - MAC주소 체계로 내트워크 내 송수신지 특정
  - 전송 과정의 충돌 문제 해결

3. 네트워크 계층
  - 메세지를 다른 네트워크에 속한 수신지까지 전달
  - 네트워크 간의 통신 : EX. 인터넷 통신
  - IP 주소 체계로 수신지 호스트와 네트워크 식별, 수신지까지 최적 경로 결정

4. 전송 계층
  - 신뢰성과 안전성 있는 전송
  - 패킷 흐름 제어, 전송 오류 점검을 통한 안정적 전송
  - '포트'로 실행 중인 응용 프로그램 식별
    - 응용프로그램 : 사용자가 특정 목적을 위해 사용하는 일반적인 프로그램

5. 세션 계층
  - 세션을 관리하는 계층
  - 세션 : 통신을 주고받는 호스트의 응용 프로그램 간 연결 상태
  - 연결 상태 생성 및 유지, 종료 시 끊어줌.

6. 표현 계층
  - 자연어를 컴퓨터 언어로 변환, 압축, 암호화 등

7. 응용 계층
  - 사용자가 이용할 응용 프로그램에 다양한 네트워크 서비스 제공
  - 실질적인 네트워크 서비스가 제고되는 계층

# 4. 네트워크 성능 지표
- 네트워크 성능 평가 지표
## 4-1. 처리율 throughput
- 딘위 시간당 네트워크를 통해 실제로 전송되는 정보량
  - 단위 : bps(bit/s), Mbps(Mbit/s), Gbps(Gbit/s), pps(packets/s)
- 실시간성 반영 - 특정 노드가 얼마만큼의 트래픽을 처리하는 중인지 판단
  - 변동성 있게 확인
  - 처리율의 평균값 활용
## 4-2. 대역폭 bandwidth
- 단위 시간동안 통신 매체를 통해 송수신할 수 있는 최대 정보량
- 높은 대역폭 : 많은 정보 송수신 가능
  ex) 8차선 도로 vs 2차선 도로
## 4-3. 패킷 손실 packet loss
- 송수신되는 패킷이 손실된 상황
- 원인 : 높은 트래픽으로 처리할 패킷이 많거나 네트워크상 장애로 인해 노드가 패킷을 처리하지 못할 경우 패킷 손실 발생
- 표현 : 유실된 패킷 / 전체 패킷의 백분위
- CMD나 ping 명령어로 확인 가능
### ping
- 수신지로 다수의 패킷을 전송해 수신지까지 도달 가능한지 여부 알려줌.
    - 몇 개의 패킷을 보내고 받았는지, 몇 퍼센트가 손실되었는지 확인 가능

```
$ ping 0.0.0.0(수신지 주소)  # 입력
PING 0.0.0.0 (0.0.0.0) : 00 data bytes
64 bytes from 0.0.0.0 : icmp_seq=0 ttl=000 time=0000 ms
...
-- 0.0.0.0 ping statistics -- # ctrl + c로 멈추고 결과 확인
0 packets transmitted, 0 packets received, 0% packet loss
...

  ```
